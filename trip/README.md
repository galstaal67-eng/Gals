אתר סטטי לתכנון וניהול הטיול, 02/09/2026 – 15/09/2026 (14 ימים).

## לשונית תכנון העלויות

אומדן שנעשה **לפני** הטיול, לזוג אחד (שני מבוגרים, חדר זוגי):

- ארבע קבוצות — טיסות, מלונות, רכב, ונסיעות/כניסות/חניונים. שלוש הראשונות
  הן הליבה; הרביעית ניתנת לכיבוי בתיבת סימון.
- כל שורה היא טווח (מ־/עד) במטבע שלה, **ניתן לעריכה** — מחליפים אומדן במחיר
  אמיתי ברגע שמזמינים, והסיכומים מתעדכנים מיד.
- סיכומים: סה"כ לזוג, לאדם, ללילה וליום, כולל הטווח המלא.
- **אוכל ושתייה אינם כלולים** בכוונה. אומדן נפרד לאלה נמצא בלשונית "מידע וציוד".

## לשונית ההוצאות בפועל

לניהול ההוצאות **במהלך** הטיול. משחזרת את הלוגיקה של גיליון ההוצאות מהטיול הקודם:

- **הזנה במטבע המקורי** — £ / € / $ / ₪, עם המרה אוטומטית לשקל.
- **שערי המרה ניתנים לעריכה** — שינוי שער מחשב מחדש את כל הטבלה מיידית,
  ומשותפים עם לשונית תכנון העלויות.
- **11 סעיפי הוצאה** — אוכל, דלק, לינה, טיסות, נסיעות, אטרקציות, חניה,
  קניות, בילויים, רפואה, אחר.
- **קיזוז בין זוגות** — חלוקה שוויונית לנפש, ואז חישוב ההעברה הנדרשת
  ("זוג 2 מעביר X ₪ לזוג 1"). האלגוריתם חמדני ותומך גם ביותר משני זוגות.
- **ניתוחים** — חלוקה לסעיפים, הוצאה לפי אדם, והוצאה יומית לאורך הטיול.
- **תקציב יעד** — אופציונלי, עם מד ניצול שמשנה צבע בחריגה.
- **ייצוא/ייבוא CSV** — עם BOM כדי ש-Excel יציג עברית תקינה. הייבוא מקבל
  תאריכים בפורמט `yyyy-mm-dd` או `dd/mm/yyyy`.

### אחסון וסנכרון

האתר עובד בשני מצבים, והמעבר ביניהם אוטומטי:

| | מסונכרן ☁️ | מקומי 📱 |
| --- | --- | --- |
| מתי | הפונקציות של Netlify זמינות | פתיחה מהדיסק, פריסה סטטית, או תקלת רשת |
| הוצאות, מטיילים, שערים | Postgres משותף לכל המכשירים | `localStorage` בלבד |
| תכנון עלויות, ציוד, ערכת צבעים | `localStorage` בכל מכשיר | `localStorage` בכל מכשיר |

הזיהוי הוא ניסיון קריאה אחד ל-`/api/state` בטעינה. כישלון אינו שגיאה — הוא
פשוט אומר "מצב מקומי", והאתר ממשיך לעבוד במלואו. מחוון בראש לשונית ההוצאות
מציג תמיד באיזה מצב אתם.

`localStorage` (מפתח `scotland2026:v1`) משמש גם במצב מסונכרן כמטמון, כך
שהדף מרונדר מיד ולא ממתין לשרת.

**מעבר ממצב מקומי לענן:** אם יש הוצאות ששמורות רק במכשיר והשרת ריק, האתר
מציע להעלות אותן בלחיצה אחת במקום למחוק אותן בשקט.

### הסכמה

```
expenses    id, spent_on, amount, currency, category, payer, note,
            created_at, deleted_at        ← מחיקה רכה
travellers  name, couple_group, sort_order
fx_rates    currency, ils_per_unit, updated_at
```

מחיקת הוצאה היא מחיקה רכה (`deleted_at`), כדי שהקשה מוטעית בטלפון לא תאבד
רשומה לתמיד. השאילתות מסננות `deleted_at IS NULL`.

### ה-API

| שיטה | נתיב | תיאור |
| --- | --- | --- |
| `GET` | `/api/state` | כל המצב המשותף בבקשה אחת |
| `POST` | `/api/expenses` | הוספת הוצאה; השרת מקצה UUID |
| `POST` | `/api/expenses/bulk` | אצווה — ייבוא CSV והעלאת נתונים מקומיים |
| `DELETE` | `/api/expenses/:id` | מחיקה רכה |
| `DELETE` | `/api/expenses` | מחיקה רכה של הכול |
| `PUT` | `/api/settings` | החלפת רשימת המטיילים ו/או השערים |

כל קלט מאומת בשרת: סכום חיובי, מטבע מרשימה סגורה, תאריך `yyyy-mm-dd`,
ואורכי שדות. אצווה עם רשומה פסולה נדחית **כולה** — אצווה חלקית גרועה יותר
מאצווה שנדחתה. עדכון המטיילים רץ בטרנזקציה, כדי שבקשה שנכשלת באמצע לא
תשאיר רשימה חלקית.

> ⚠️ **אין אימות משתמשים.** כל מי שמגיע לכתובת יכול לקרוא ולערוך את ההוצאות.
> זו הייתה החלטה מודעת. להוספת קוד טיול משותף בהמשך צריך לבדוק משתנה סביבה
> אחד ב-`netlify/lib/shared.mts` ולהוסיף מסך כניסה — שינוי קטן.

### עריכת המסלול

כל התוכן יושב ב-`assets/js/data.js` במבנה אחד (`TRIP`). כדי לשנות יום —
עורכים את האובייקט שלו; אין צורך לגעת ב-HTML או ב-JS. שדות מרכזיים לכל יום:

```js
{
  n: 7, date: "2026-09-08", dow: "שלישי",
  title: "...", region: "היילנדס",   // region מזין את הצ'יפ שמעל המפה ואת גרף הק"מ
  mapLabel: "הגעה",                   // אופציונלי — גובר על region בצ'יפ בלבד
  mode: "drive",                      // flight | train | drive | city
  drive: { km: 70, hours: 1.5, note: "..." },
  hotel: { name: "...", area: "...", lat, lng, booked: true },
  plan:  [{ time: "09:00", text: "..." }],
  tips:  ["..."],
  points: [{ name: "...", lat, lng, type: "hike" }],  // type קובע את האייקון
  path:  [[lat, lng], ...],           // הקו על המפה
  pathMode: "drive"
}
```

## התאמה לניידים

נבדק ב-Chromium ברוחב 390px בכל הלשוניות:

- אפס גלילה אופקית. פריטי grid מקבלים `min-width: 0` מפורש — בלעדיו תוכן רחב
  (טבלה עם `min-width`) מנפח את כל הרשת ומוציא את הדף מהמסך.
- **טבלאות נפרסות לכרטיסים** מתחת ל-640px במקום גלילה הצידה. כותרת כל תא
  מגיעה מ-`data-label` דרך `::before`.
- אזורי מגע של 44px לכל הכפתורים, הלשוניות והצ'יפים תחת `@media (pointer: coarse)`.
- שדות קלט ב-16px בדיוק על מסכי מגע — מתחת לזה ספארי מזנק זום בעת מיקוד.
- **המפה נעולה עד להקשה** במסכי מגע. בלי זה אצבע על המפה חוטפת את גלילת הדף
  ואי אפשר לעבור אותה.
- טופס בעמודה אחת, סרגל לשוניות שגולל את הנבחרת לתצוגה, ו-`theme-color`
  לסרגל הדפדפן.

ניווט ל-Google Maps.
